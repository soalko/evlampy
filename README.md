# Evlampy Messenger

## О проекте

**Evlampy** — это учебный клиент-серверный мессенджер на C++ с шифрованием сообщений и модульной архитектурой. Проект демонстрирует разбиение приложения на логические компоненты, использование CMake, подключение внешних библиотек, а также организацию unit-тестов и сценарных тестов.

В проекте реализованы:

- регистрация и авторизация пользователей;
- обмен личными и групповыми сообщениями;
- шифрование сообщений на стороне клиента;
- хранение истории переписки и статусов сообщений;
- управление контактами и группами;
- минимальный графический интерфейс для работы с мессенджером;
- набор unit-тестов и тестовых сценариев для отладки.

## Структура репозитория

```text
include/        публичные заголовочные файлы
src/            исходный код приложения
  chat/         клиент, сервер, сообщение, сценарий main
  encryption/   стратегия шифрования и фабрика ключей
  network/      транспортный слой и протокол обмена
  patterns/     паттерны Command, Singleton и др.
  gui/          графический интерфейс
tests/          unit-тесты, сценарии, тестовые утилиты и документация
build/          конфигурация основного CMake-проекта в текущем workspace
build-tests/    отдельная директория для сборки тестов
build-gui/      отдельная директория для сборки GUI-версии
```

## Используемые технологии и библиотеки

- **C++17** — основной язык проекта;
- **OpenSSL** — криптография, RSA и AES-GCM;
- **Threads** — многопоточность и синхронизация;
- **GoogleTest** — unit-тестирование;
- **Qt 6 Widgets/Core/Gui** — минимальный кроссплатформенный GUI;
- **Cocoa / AppKit** — альтернативный GUI-вариант для macOS.

## Сборка проекта

### Основное приложение

Если проект открыт как обычный CMake-проект, используйте стандартную out-of-source-сборку:

```bash
cmake -S . -B build
cmake --build build -j4
```

После сборки будет доступен исполняемый файл `target_exec`.

### Сборка тестов

Для тестов используется отдельная директория:

```bash
cmake -S . -B build-tests -DBUILD_TESTS=ON
cmake --build build-tests -j4
```

### Сборка GUI

В проекте предусмотрен минимальный графический интерфейс. В зависимости от платформы используется один из вариантов:

- `src/gui/MessengerWindow.cpp` — Qt-версия GUI;
- `src/gui/main_gui.mm` — macOS-версия на Cocoa/AppKit.

Если у вас настроена отдельная GUI-сборка, используйте отдельную директорию, например:

```bash
cmake -S . -B build-gui -DBUILD_GUI=ON
cmake --build build-gui -j4
```

## Запуск

### Консольная версия

```bash
./build/target_exec
```

Консольный сценарий демонстрирует:

- регистрацию двух пользователей;
- вход в систему;
- отправку личного сообщения;
- создание группы;
- отправку группового сообщения;
- удаление сообщения для всех участников.

### Графический интерфейс

```bash
./build-gui/messenger_gui
```

Если вы запускаете GUI-сборку на macOS, приложение открывает минимальное окно с полями для регистрации, входа, отправки сообщений и управления группами.

## Тестирование

### Unit-тесты

Unit-тесты находятся в папке `tests/unit/` и покрывают основные классы проекта:

- `Message`
- `MessageProtocol`
- `TcpClient`
- `TcpServer`
- `AES256GCMStrategy`
- `OpenSSLKeyFactory`
- `ChatServer`
- `ChatClient`
- `Observer`
- `Command` и `Logger`

Запуск всех тестов:

```bash
cd build-tests
ctest --output-on-failure
```

### Тестовые сценарии

Сценарные мини-программы находятся в `tests/scenarios/` и моделируют ключевые этапы работы системы:

- регистрация и авторизация;
- отправка личного сообщения;
- создание и использование группового чата;
- удаление сообщения для всех;
- административные действия;
- повторный вход после перезапуска.

## Пример сценария работы

1. Пользователь регистрируется и получает локальную пару ключей.
2. Пользователь входит в систему по логину и паролю.
3. Клиент создаёт защищённое сообщение и отправляет его адресату.
4. Сервер сохраняет зашифрованные данные и пересылает их получателю.
5. Получатель расшифровывает сообщение локально на своей стороне.

## Примечания

- Приватные ключи пользователей не должны передаваться по сети.
- История сообщений и данные пользователей хранятся в зашифрованном или защищённом виде в соответствии с моделью проекта.
- Проект демонстрационный и предназначен для изучения архитектурных решений, паттернов проектирования, CMake и unit-тестирования.
